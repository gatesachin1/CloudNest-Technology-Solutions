AWS S3 (Simple Storage Service) is not just for storing files — it is also one of the most reliable and cost-effective ways to host a static website. With S3, you get 99.999999999% (11 9s) durability, automatic scaling, and hosting costs that are typically under ₹50/month for a typical business website.

In this guide, we'll walk you through setting up S3 static website hosting both manually (via the AWS Console) and automatically using Terraform.

What is a static website? A site made of HTML, CSS, and JavaScript files — no server-side processing. This includes most marketing websites, portfolio sites, documentation sites, and landing pages.
1

Create an S3 Bucket with Your Domain Name

For S3 static website hosting to work seamlessly with a custom domain, the bucket name must exactly match your domain name.

In the AWS Console, go to S3 → Create bucket:

  • Bucket name: yourdomain.com (e.g. cloudnesttechnologysolutions.in)
  • AWS Region: Choose the region closest to your users. For India, ap-south-1 (Mumbai) is ideal for latency.
  • Leave all other settings at defaults for now.

If you also want www.yourdomain.com to work, create a second bucket named www.yourdomain.com. This bucket will only redirect to the root domain (see Step 5).

2

Enable Static Website Hosting

Go to your bucket → Properties → Static website hosting → Enable.

  • Index document: index.html
  • Error document: index.html (or 404.html if you have one)

After saving, AWS will show you a website endpoint like:

http://cloudnesttechnologysolutions.in.s3-website-ap-south-1.amazonaws.com

Note this endpoint — you'll use it when configuring DNS.

3

Disable the Public Access Block

By default, AWS S3 blocks all public access. For a public website, you need to allow it. Go to your bucket → Permissions → Block public access → Edit → uncheck all four options → Save.

Important: Only do this for buckets that are intentionally public. Never disable the public access block on buckets storing sensitive data like backups, user uploads, or database exports.
4

Add a Bucket Policy for Public Read

Go to your bucket → Permissions → Bucket policy → Edit. Paste this policy (replace the bucket name with yours):

{ "Version": "2012-10-17", "Statement": [ { "Sid": "PublicRead", "Effect": "Allow", "Principal": "*", "Action": "s3:GetObject", "Resource": "arn:aws:s3:::cloudnesttechnologysolutions.in/*" } ] }

This allows anyone on the internet to read (download) files from the bucket — which is exactly what you want for a public website.

5

Upload Your Website Files

Upload your index.html, CSS, JavaScript, and image files to the bucket, preserving the folder structure. The easiest way is the AWS Console drag-and-drop, but for production use, the AWS CLI is faster:

aws s3 sync ./dist s3://cloudnesttechnologysolutions.in \ --delete \ --cache-control "max-age=86400"

The --delete flag removes files from S3 that no longer exist in your local directory. The --cache-control header tells browsers to cache files for 24 hours, improving load times.

6

Configure the www Redirect Bucket

For your www.yourdomain.com bucket, enable static website hosting but choose "Redirect requests for an object" and set the host name to your root domain (yourdomain.com). This way, any visitor going to www.cloudnesttechnologysolutions.in will be redirected to cloudnesttechnologysolutions.in automatically.

7

Automate It All with Terraform

Doing this manually every time you set up a new project is tedious and error-prone. Here's the Terraform equivalent of everything above:

resource "aws_s3_bucket" "root" { bucket = "cloudnesttechnologysolutions.in" force_destroy = true } resource "aws_s3_bucket_website_configuration" "root" { bucket = aws_s3_bucket.root.id index_document { suffix = "index.html" } error_document { key = "index.html" } } resource "aws_s3_bucket_public_access_block" "root" { bucket = aws_s3_bucket.root.id block_public_acls = false block_public_policy = false ignore_public_acls = false restrict_public_buckets = false } resource "aws_s3_bucket_policy" "root" { bucket = aws_s3_bucket.root.id depends_on = [aws_s3_bucket_public_access_block.root] policy = jsonencode({ Version = "2012-10-17" Statement = [{ Sid = "PublicRead" Effect = "Allow" Principal = "*" Action = "s3:GetObject" Resource = "arn:aws:s3:::cloudnesttechnologysolutions.in/*" }] }) }

Run terraform init && terraform apply and your entire infrastructure is set up in under a minute, reproducibly, every time.

Connecting Your Domain (Route 53)

In AWS Route 53, create an A record for your root domain as an Alias record pointing to your S3 website endpoint. Do the same for www pointing to the www bucket's endpoint.

DNS propagation takes a few minutes to a few hours. After that, http://cloudnesttechnologysolutions.in will serve your website directly from S3.

Want HTTPS? S3 static hosting only supports HTTP. To add HTTPS (SSL), you'll need to add CloudFront in front of S3. We cover that in a separate guide, or you can contact us and we'll set it up for you.

How Much Does It Cost?

S3 pricing in the Mumbai (ap-south-1) region:

  • Storage: ₹1.95 per GB per month (most websites are under 50 MB)
  • Requests: ₹0.30 per 10,000 GET requests
  • Data transfer out: ₹6.90 per GB after the first 100 GB/month

For a typical business website with 5,000 monthly visitors, the total S3 cost is usually under ₹50 per month. That's significantly cheaper than shared hosting, with far better reliability.
